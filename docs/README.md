# InterLink ⇄ Autolauncher Plugin

This repository contains a custom InterLink sidecar that offloads Kubernetes Pods to BSC MareNostrum/AMD-CTE via the **Autolauncher** (which wraps SLURM + Singularity/Apptainer).

**What it does**
- Accepts InterLink plugin API calls (`/create`, `/status`, `/delete`, `/getLogs`)
- Generates an Autolauncher JSON, stages it on the AMD login node over SSH, and calls `autolauncher.py`
- Tracks UID → SLURM JobId mapping and exposes Pod status & logs by querying `squeue/sacct` and job output files

> InterLink edge-node & plugin concepts come from the official docs. See: Edge node deployment, Plugin API, and Developers guide.
> 
> - Edge node: interLink remote components & installer, OAuth2-Proxy, Helm values (`~/.interlink/manifests/values.yaml`)  
> - Plugin API: `/create`, `/delete`, `/status`, `/getLogs`  
> - `interlink.yaml` holds plugin endpoints for the API server

## Topology

```
K8s (master 192.168.0.249 + worker 192.168.0.152)
             │  Virtual Kubelet (via Helm chart)
             ▼
      InterLink API server + OAuth2 Proxy  (on Autolauncher VM 192.168.0.98)
             │  (HTTP/Unix socket)
             ▼
   Autolauncher Plugin (this repo)  ──(SSH)──►  AMD-CTE login (amdlogin1.bsc.es)
                                                 │
                                                 └── submits sbatch and runs Singularity on GPFS
```

## Quick start

### 1) On **autolauncher VM** (`192.168.0.98`)

```bash
git clone https://example.org/interlink-autolauncher-plugin.git
cd interlink-autolauncher-plugin/scripts
./bootstrap_autolauncher.sh
```

- The script will:
  - Install the InterLink remote components using the **interlink-installer** and start them.
  - Set up this plugin under **systemd** at `http://127.0.0.1:8001/health`.
  - Ask your **BSC AMD-CTE username** and help you copy an **SSH key** to `amdlogin1.bsc.es` (no password stored).
  - Upload `plugin/hpc/autolauncher.py` to `~/.autolauncher/autolauncher.py` on AMD.
  - Leave a config at `/etc/autolauncher-plugin/config.yaml` (edit to match your GPFS paths and defaults).

### 2) On **K8s master** (`192.168.0.249`)

```bash
git clone https://example.org/interlink-autolauncher-plugin.git
cd interlink-autolauncher-plugin/scripts
./bootstrap_k8s_master.sh 192.168.0.98 <ssh-user-on-autolauncher>
```

- This installs/updates the **InterLink Helm chart** using the `values.yaml` produced on the autolauncher.
- It then applies a **test pod** pinned to the InterLink virtual node.

If `kubectl logs` fails, approve the CSR as documented:

```bash
kubectl get csr
kubectl certificate approve csr-xxxxx
kubectl logs test-tunnel
```

## Configuration

Edit `/etc/autolauncher-plugin/config.yaml`:

- `hpc.login_host`: `amdlogin1.bsc.es`
- `hpc.user`: your BSC username (key-based SSH recommended)
- `hpc.remote_base_dir`: base working dir on `/gpfs/projects/bsc70/...`
- `hpc.cluster`: `amd | mn4 | p9 | local`
- `hpc.image_map`: map k8s images to local Singularity images if Internet is restricted
- `plugin.port`: defaults to `8001` (referenced by InterLink API)

## How it maps k8s → SLURM via Autolauncher

- CPU/GPU requests/limits are converted to `cpus-per-task` and `--gres=gpu:X`
- QoS, time and other options come from config defaults (override later via annotations if desired)
- The container command/args are wrapped as a bash command inside the Singularity execution generated by Autolauncher (AMD profile uses `--rocm`).

## Troubleshooting

- Check InterLink overall health from the autolauncher VM:
  ```bash
  curl -v --unix-socket ${HOME}/.interlink/.interlink.sock http://unix/pinglink
  ```
- Plugin logs: `journalctl -u autolauncher-plugin -f`
- Remote job output: `${remote_base_dir}/${podUID}/output/*_{SLURM_JOBID}_out.txt`
